# 경고 철회 판단기 순위 (FR-RPT-105, 11/11)

학생이 경고 철회를 요청하면 판단기가 다시 보고 철회 또는 유지를 정한다. 정답을 정해 둔 가짜 사례를 규칙 판단기와 Gemini에 똑같이 넣고, 판마다 한 가지만 바꿔 가며 쟀다. 결정 기록은 [결정.md 34](결정.md).

- 사례 50개 `src/test/resources/eval/appeal-cases.json`: 고칠 때 본 35개(dev) + 마지막 확인용 15개(holdout, 고치는 동안 안 봄). 이름·학번 없는 가짜
- 모델 `gemini-3.5-flash-lite`, 무료 키. Gemini 호출 약 280번, 한도 오류(429) 0번
- 돌리는 법: `EVAL_SET=dev|holdout|all ./mvnw test -Dtest=ReviewerEval -Dsurefire.failIfNoSpecifiedTests=false` → `target/eval/reviewer-eval.md`
- 같은 표(화면용): https://claude.ai/artifact/XMac5pwXZUiAhDCGeei3dN

## 판마다 바꾼 것과 점수가 바뀐 까닭

1. **Gemini 4판 (채택):** 3판에 "인정이란 신고가 문제 삼은 결과를 인정하는 것"을 덧붙였다. "창문을 열었다가 닫았다"를 인정으로 봐서 틀렸던 C17이 맞았다. 고칠 때 안 본 holdout 15개도 다 맞혔다.
2. **Gemini 3판:** 2판에 "학생이 신고된 행동을 스스로 인정하면 유지, 봐 달라고만 하는 건 부인이 아님"을 넣었다. 본인 인정 3개가 맞았지만, 창문을 열었다가 닫았다는 글까지 인정으로 봐서 1개(C17)가 새로 틀렸다.
3. **Gemini 2판:** 남은 물건마다 방 비품인지(`roomFixture`) 표시를 붙였다. 의자·책상·모니터·쓰레기통을 두고 간 물건으로 보던 오류 5개가 없어져 심각 오류가 0이 됐다. 학생 본인 인정 3개는 여전히 철회로 틀렸다.
4. **규칙 판단기 v2 (Gemini가 실패할 때 대신 봄):** 규칙 판단기에도 같은 비품 목록(`RoomFixtures`)을 넣었다. 비품 오류는 다 없어졌고, 남은 6개는 모두 학생 본인 인정이다. 규칙은 학생 글을 읽지 않아서 이건 못 맞힌다.
5. **Gemini 0판:** 처음 만든 그대로다. 35개 중 5번은 Gemini가 503(서버 바쁨)으로 답하지 못해 규칙 판단기가 대신 답했다. 그래서 Gemini만의 실력보다 높게 나왔다.
6. **Gemini 1판:** "503이면 1초, 2초 쉬고 두 번 더"만 넣었다. 규칙으로 넘어간 게 0번이 되면서 Gemini만의 실력이 드러났다. 방 비품을 두고 간 물건으로 보는 오류가 많아 0판보다 낮다.
7. **규칙 판단기 v1:** 남은 물건 중 가장 높은 확신도가 0.8 이상이면 유지하는 규칙만 있다. 방 비품도 두고 간 물건으로 봐서 철회해야 할 경고를 유지했다. 학생 본인 인정도 못 맞힌다.

## 세는 법

- **점수:** 학생에게 실제로 적용되는 결정으로 센다. 판단기가 "유지"라고 해도 확신도가 0.8(`mspace.appeal.min-confidence`)보다 낮으면 철회된다.
- **심각 오류:** 철회해야 할 경고를 유지한 것이다. 학생이 받지 않아야 할 벌칙을 받는다.
- **정답 기준:** 방 비품만 남았으면 철회, 학생이 스스로 인정하면 유지(지영 확정).
- **holdout 15개:** 고치는 동안 보지 않고 마지막에 한 번만 쟀다. 답을 외우듯이 맞춘 게 아닌지 보려는 것이다.

## 새 사례 20개로 다시 시험 (11/11 지영 "새 가짜 데이터로 시험")

판단기를 고친 뒤에 처음 보는 사례 20개(`set: fresh`, N01–N20)를 새로 만들어 한 번만 쟀다. 고치지 않았다.

| 판단기 | 맞춤 | 심각 오류 | 건당 시간 평균 / 최대 |
|---|---|---|---|
| Gemini 4판 (`gemini-v2`) | 19/20 (95%) | 1 | 1.2초 / 2.4초 |
| 규칙 판단기 v2 (`rules-v2`) | 17/20 (85%) | 0 | 0초 |

- Gemini가 틀린 것 N13: "쏟은 건 맞는데 휴지로 다 닦고 나왔어요"를 인정으로 보고 유지했다. 쏟은 행동만 인정하고 문제 된 결과(어질러 둔 채 나옴)는 부인한 경우라 정답은 철회.
- 규칙이 틀린 3개는 모두 학생 본인 인정(N09, N11, N15).
- 70개 전체로 치면 Gemini 69/70(98.6%), 규칙 61/70(87%).

## Claude가 직접 정한 것 (팀 확인 없이)

정확도 숫자는 아래 판단 위에 서 있다. 바꾸면 숫자도 바뀐다.

| 무엇 | 정한 내용 | 왜 | 확인할 사람 |
|---|---|---|---|
| 사례 70개 | 모두 Claude가 만든 가짜. 실제 학생 글이 아님 | 시범 운영 전이라 실제 철회 요청이 없음 | 시범 운영 뒤 실제 요청으로 다시 재기 |
| 사례마다 정답 | 70개 정답(철회/유지)을 Claude가 붙임. 큰 기준 두 개(비품만 남음=철회, 본인 인정=유지)만 지영 확정 | 기준을 사례 하나하나에 적용한 것은 Claude 판단 | 팀원이 사례 몇 개 골라 정답에 동의하는지 보기 |
| "인정"의 범위 | 문제 된 결과(시끄러웠다, 어질러 둔 채 나왔다)를 인정해야 인정. "열었다가 닫았다", "쏟았지만 닦았다"는 인정 아님 | 행동만 인정하고 결과를 부인하면 사실 확인이 안 됨 | 지영 |
| 허위 신고 경고(FALSE_REPORT) | 학생 신고 경고와 같은 원칙. 학생이 착각을 인정하면 유지 | 기존 지시문 4번과 같게 | 지영 |
| 기준과 같은 확신도 | 0.80 = 기준 이상 → 유지 | `warn-min-confidence` 이상이면 경고하는 core 코드와 같게 | - |
| 방 비품 목록 | chair, desk, table, dining table, whiteboard, monitor, tv, trash can, clock, air conditioner, couch, bench | 실제 방 비품과 카메라 이름을 몰라 일반 스터디룸 기준으로 가정 | 수연(물건 이름), 지영(실제 방 비품) |
| 점수 세는 법 | 판단기 답이 아니라 학생에게 실제 적용되는 결정으로 셈(유지라도 확신도 0.8 미만이면 철회) | 학생이 실제로 받는 결과가 중요해서 | - |
| 심각 오류 | "철회해야 할 걸 유지"만 셈. "유지해야 할 걸 철회"는 보통 오류 | 받지 않아야 할 벌칙이 더 큰 피해(확인 불가 = 벌칙 없음 원칙) | - |

| holdout 15개 | 고치는 동안 결과를 안 보고 마지막에 한 번만 잼 | 시험 문제를 외워서 맞춘 게 아닌지 보려고 | - |
| 새 사례 20개에서 틀린 N13 | 고치지 않고 그대로 둠 | 고치면 처음 보는 사례 시험이 아니게 됨. 고칠지는 지영 결정 대기 | 지영 |

## 남은 것

- 사례는 모두 가짜다. 시범 운영 때 실제 요청으로 다시 재면 숫자가 달라질 수 있다.
- 방 비품 목록은 일반 스터디룸 비품으로 **가정**했다. 실제 방 비품과 카메라 모델 이름(수연)으로 확인해야 한다.
